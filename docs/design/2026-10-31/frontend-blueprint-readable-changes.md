## 바꾼 정보 구조

원본의 12개 장을 비슷한 비중으로 읽던 흐름을 바꿨다. 처음에는 1분 요약을 읽고, Part 1 프로젝트, Part 2 사용자·팀 역할, Part 3 데이터·추천, Part 4 구현·회의 계획을 따라간다. Part 5에서 원본 12개 장을 목적별로 찾아본다.

본문은 핵심 설명 다음에 실제 이용 사례를 두고 기술 기준을 연결한다. API 필드를 먼저 나열하기보다 기사를 누르고 본문을 읽는 상황부터 설명한다. 저장 성공과 분석 준비 완료, 행동 한 건의 event_id와 전송 묶음의 batch_id를 나눠 설명했다.

## 시각화와 탐색

전체 개요·시스템 구조·사용자 여정·팀 역할·행동 발생 시점·데이터 파이프라인·CTR 학습·구현 로드맵을 HTML/CSS 연결 그림 8개로 표현했다. 역할별 색과 역할명을 함께 표시한다. 그림의 항목을 누르면 관련 본문이나 기술 상세로 이동한다. 외부 라이브러리·폰트·이미지는 필요 없다.

데스크톱에는 고정형 사이드 목차와 현재 섹션 표시를 두고, 모바일에는 접이식 목차를 둔다. 기술 상세는 개별 펼치기와 모두 펼치기·접기를 지원한다. 상세 링크는 접힌 영역을 자동으로 펼친다. 키보드 포커스 표시와 본문 이동 링크를 제공한다.

모바일은 흐름도를 세로로 연결하고 넓은 표를 열 제목이 붙은 카드로 표시한다. 인쇄 스타일은 탐색 도구를 숨기고 표·연결 그림을 지면용으로 조정한다. 인쇄 이벤트에서는 접힌 상세를 펼친 뒤 종료 시 기존 상태로 되돌린다.

## 보존한 기술 의미

원본 v0.6의 12개 장은 문단·표·JSON·출처를 삭제하지 않고 Part 5에 재배치했다. 제목 계층만 조정했으며 생성 스크립트가 역변환해 내용 일치를 검사한다. API·오류·식별자·쿠키·이벤트 정의·CTR 분모·클릭 관측 기간·피처·데이터 누출 방지·저장 수락·중복·충돌·재시도·보관·권한 규칙을 보존했다.

기존 구현·테스트는 2026년 10월 29일의 확인 기록으로 표시했다. 초기 관심사 입력은 MVP 제외, Cloud Storage → BigQuery는 권장 설계안, 행동 API·모델 연결은 미완료라는 상태를 유지했다. 50%·1초 등 임계값을 확정된 규칙으로 바꾸지 않았다. 읽기 시간·이해도·성능을 새로 측정했다고 주장하지 않는다.

## 확인한 것과 남은 것

- 두 원본 파일 SHA-256이 기존 값과 일치한다.
- 원본 12개 장의 본문이 기술 상세에 보존된다.
- JSON 예시 2개의 구문, HTML ID 중복과 내부 링크 대상을 검사했다.
- 데스크톱 화면에서 연결 그림·사이드 목차·현재 섹션 표시를 확인했다.
- 상세 바로가기의 자동 펼침, 모두 펼치기 12개, 모두 접기와 Enter 키 조작을 확인했다.
- 모바일 화면에서 세로 연결 그림·카드형 결정표를 확인했다. 전체 상세를 펼쳐도 페이지 가로 넘침과 영역 밖 코드·표·그림이 없었다.
- 인쇄 CSS와 인쇄 전후 상세 펼침·복귀 처리를 확인했다. 실제 인쇄 미리보기의 페이지 나눔과 PDF 전체 시각 검증은 완료하지 못했다.

인쇄 미리보기 시 도구가 문서 대신 ChatGPT 앱 창을 대상으로 인식했다. 자동 승인 검토가 무관한 사적 화면 캡처 위험을 이유로 캡처를 거절해 해당 검증은 중단했다. 실제 인쇄물의 페이지별 레이아웃 확인은 남아 있다. 사용자 이해도와 모든 브라우저·화면 크기의 접근성 검사를 대신하는 검증은 아니다.
