# 11월 5일 멘토 미팅 · 합성 로그

이 문서는 합성 로그 논의만 모은 미팅 메모다. 팀장님께 전달할 통합 자료는 추후 별도로 만든다.

흐름 설명용 [5장 슬라이드](합성-로그-흐름-설명.pptx)는 입력, 모델 판단, 로깅 서버 전송, 저장 결과를 차례로 보여준다.

## 멘토가 제시한 방향과 이번 제안

멘토가 제시한 큰 방향은 **페르소나를 입힌 에이전트가 브라우저에 접속해 기사를 클릭하는 것**이다. 이번 주에는 화면 없이 에이전트가 합성 행동 이벤트를 직접 로깅 서버에 보내는 방식을 제안한다. 직접 전송이 숙제 범위에 맞는지는 미팅에서 확인해야 한다. 웹 완성 뒤 Playwright로 실제 화면을 조작하는 단계는 아직 구현하지 않았다.

## 11월 5일 현재 구현

- `scripts/synthetic-logging-agent.mjs`가 입력 파일의 `persona`와 기사 `article_id`·제목을 OpenRouter DeepSeek Flash에 보내 클릭할 기사 하나 또는 클릭 없음을 받는다. 기본 모델 ID는 `deepseek/deepseek-v4.1-flash-1017`이다.
- 입력 목록의 각 기사에 `request_id`·`impression_id`를 붙여 로깅 서버 `POST /internal/served`로 보낸다. 모델이 기사를 고르면 해당 `impression_id`로 `article_open` 한 건을 `POST /events`에 보낸다. `source=simulator`로 저장해 브라우저 행동과 구분한다.
- 기본 반복 간격은 한 회가 끝난 뒤 10초다. 모델 호출 시간과 네트워크 시간을 포함한 정확한 10초 주기는 아니다. `--once`로 한 번만 실행할 수 있다.
- 로깅 서버의 `accepted`는 로컬 SQLite 수락이다. 5분 JSONL 내보내기와 GCS 업로드 완료를 뜻하지 않는다. 재시도 큐가 없어 호출 실패 시 스크립트가 종료된다.
- 체류 시간, 실제 화면 노출, 쿠키 발급, 클릭 이후 읽기, GCS 직접 전송은 구현하지 않았다. 현재 로깅 서버의 이벤트 계약에는 체류 시간 필드가 없다.

## 시연 페르소나와 카테고리 근거

`examples/synthetic-personas.json`에는 IT·과학, 스포츠, 문화, 사회, 생활에 관심이 다른 가상 독자 5명을 두었다. `scripts/make-synthetic-contexts.mjs`는 이 독자들과 프런트엔드의 가상 기사 8건을 결합해 입력을 만든다. 이는 **프런트엔드 시연 카테고리**를 기준으로 한 초안이다. 같은 기사 목록을 주고 독자별 클릭 선택이 다른지 살피기 위한 설계이며, 그 차이와 추천 품질을 아직 측정하지 않았다.

태원님 백엔드의 `exports/news_articles.dump`는 현재 접근 권한으로 읽지 못했다. 프런트엔드 공용 작업 폴더에 있는 백엔드 API 명세 초안에는 `category`가 DB의 대분류 문자열, `subcategory`가 소분류 문자열이라고 적혀 있다. 이 초안은 아직 이 브랜치에 포함되지 않았다. 샘플 값 `스포츠`와 `스포츠포토`는 전체 목록이 아니다. DB를 읽을 수 있게 되면 실제 카테고리·기사 수를 확인하고 페르소나와 입력 기사를 조정한다.

## 멘토에게 확인할 질문

1. 이번 주에는 브라우저 없이 직접 전송한 합성 로그를 허용하는가? 아니면 에이전트가 웹을 조작해야 하는가?
2. 합성 로그에서 목록 제공 기록과 클릭만 우선 보내도 되는가? 체류 시간을 요구한다면 어떤 이벤트 계약과 측정 의미를 사용할 것인가?
3. 페르소나 다양성을 어떤 기준으로 평가할 것인가? 관심사별 클릭 차이와 클릭하지 않는 경우를 확인하면 충분한가?
4. 합성 로그를 실제 독자 로그·학습·평가 데이터와 어떻게 분리할 것인가?
5. 백엔드의 실제 카테고리와 기사 ID를 언제, 어떤 경로로 받을 수 있는가?
