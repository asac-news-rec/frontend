# 개인화 뉴스 추천 유사 프로젝트 조사

프론트엔드 구현 자료는 [프론트엔드 개발 참고 자료](frontend-reference.md)에 별도로 정리했다.

조사일: 2026-10-30. 공개 저장소의 README, 일부 구현 코드, 공식 데이터셋 설명을 확인했다. 설치와 실행, 성능 재현은 수행하지 않았다. 아래 활용 의견은 우리 프로젝트에 대한 제안이며 도입 확정 사항이 아니다.

## 우리 프로젝트의 비교 기준

독자의 뉴스 이용 기록을 수집해 다음에 읽을 기사를 추천한다. 사용자 설명을 기준으로 화면과 비로그인 방문자 식별까지 구현했다. 실제 행동 수집, 클라우드 저장, 추천 API, CTR 모델은 연결 전이다. 초기 관심사 입력은 MVP에서 제외했다.

회의에서 검토할 데이터 경로는 `수집 API → Cloud Storage 원본 파일 → BigQuery 배치 처리`다. 실시간 반영은 초기 목표가 아니다. 이 경로는 구축 완료된 시스템이 아니다. 현재 저장소 README의 준비 단계 설명과 사용자 설명은 다르므로, 이 문서는 사용자가 설명한 진행 상황을 기준으로 한다.

## 참고할 데이터 구조와 기술

### MIND의 노출 단위 데이터

[MIND 공식 설명](https://msnews.github.io/)은 노출 시점 이전의 클릭 이력과, 해당 노출에 포함된 기사별 클릭·미클릭 정보를 함께 제공한다. [NRMS 예제](https://github.com/recommenders-team/recommenders/blob/main/examples/00_quick_start/nrms_MIND.ipynb)는 다음 입력 구조를 설명한다.

- 기사 데이터: 기사 ID, 카테고리, 제목, 요약 등의 기사 정보
- 행동 데이터: 노출 ID, 독자 ID, 노출 시각, 과거 클릭 기사 목록, 노출 기사별 클릭 라벨

우리 서비스에서는 비로그인 방문자 ID, 기사 ID, 노출 ID로 행동을 연결하는 구조를 참고할 수 있다. 같은 노출 묶음에서 클릭한 기사와 클릭하지 않은 기사를 구분할 수 있어야 한다.

다음은 설명용 가상 학습 데이터이며 실제 수집 결과가 아니다.

| 방문자 ID | 노출 ID | 후보 기사 ID | 노출 전에 읽은 기사 | 클릭 라벨 |
|---|---|---|---|---|
| V001 | R100 | A10 | A02, A07 | 1 |
| V001 | R100 | A11 | A02, A07 | 0 |

우리 수집 설계에서는 실제 화면 노출의 기준, 이벤트 시각의 단위와 시간대, 클릭을 기다리는 기간, 중복 이벤트 처리 규칙을 추가로 정해야 한다. MIND의 노출 목록을 그대로 브라우저의 실제 가시성 측정과 동일하게 해석하지 않는다. 미클릭은 비선호를 확정하는 표현이 아니다.

### EB-NeRD의 전처리 함수

[행동 전처리 구현](https://github.com/jppol-ai/ebnerd-benchmark/blob/main/src/ebrec/utils/_behaviors.py)에는 다음 함수가 있다.

| 함수 | 제공하는 처리 | 우리 적용 의견 |
|---|---|---|
| `create_binary_labels_column` | 노출 기사와 클릭 기사로 이진 라벨 생성 | BigQuery에서 노출과 클릭을 연결하는 규칙의 참고 자료 |
| `create_dynamic_history` | 시간에 따라 과거 이력 구성 | 추천 시점 이전 행동만 입력에 포함하는 처리 참고 |
| `truncate_history` | 이력 길이 제한 | 최근 일정 개수의 기사로 입력 크기 통일 |
| `sampling_strategy_wu2019` | 노출 후보 중 미클릭 기사 샘플 추출 | 학습량을 조절하는 선택지. 추출 비율을 실제 CTR로 해석하지 않도록 주의 |

구현은 Python의 Polars를 사용한다. 우리 배치 작업은 처리 규칙을 BigQuery SQL로 옮기거나 Python에서 활용할 수 있다. Polars와 BigQuery를 모두 도입해야 하는 것은 아니다.

### Recommenders의 모델과 평가

[NRMS 예제](https://github.com/recommenders-team/recommenders/blob/main/examples/00_quick_start/nrms_MIND.ipynb)는 기사 제목과 과거 읽기 기록으로 후보 기사의 점수를 계산한다. 관심사 설문 없이 행동으로 독자 표현을 학습한다. 예제는 TensorFlow, MIND 입력 처리, 영어 GloVe 임베딩을 사용한다. 한국어 기사에는 어휘와 임베딩 구성을 별도로 맞춰야 한다.

같은 예제는 AUC, MRR, NDCG@5·10을 사용한다. 이 평가는 클릭한 기사를 얼마나 높은 순위에 두는지 비교하는 데 참고할 수 있다. 오프라인 점수는 실제 서비스 CTR 개선의 증거가 아니며, 모델의 추천 점수가 보정된 클릭 확률이라는 뜻도 아니다.

우리 검증에는 시간 순서에 따른 학습·평가 분리, 미래 클릭의 입력 유입 방지, 방문자별 결과 차이, 이력이 부족한 방문자의 결과를 포함할 필요가 있다. 추천 근거는 별도로 정의해야 하며 모델의 attention 값을 곧바로 설명으로 간주하지 않는다.

### CHAMELEON과 POPROX의 구조

[CHAMELEON README](https://github.com/gabrielspmoreira/chameleon_recsys/blob/master/README.md)는 기사 내용 표현을 만드는 모듈과 다음 기사 추천 모듈을 분리한다. 세션의 클릭 순서를 활용하는 방향은 비로그인 방문자 추천의 참고 대상이다. 기존 TensorFlow 1.12 구현을 도입하기 전에는 실행 환경과 수정 비용을 확인해야 한다.

[POPROX README](https://github.com/CCRI-POPROX/poprox-recommender/blob/main/README.md)는 Docker 기반 로컬 엔드포인트, 배치 추론, DVC 기반 데이터·모델 관리와 평가 절차를 설명한다. 우리에게는 학습 작업과 추천 제공을 분리하는 방식이 참고 대상이다. DVC와 Docker의 도입 필요성은 모델 관리와 배포 범위가 정해진 뒤 판단할 수 있다.

## 우리 프로젝트의 활용 의견

현재 우선 참고 대상은 MIND의 데이터 구조와 EB-NeRD의 전처리 규칙이다. 방문자 식별에 노출과 클릭을 연결한 뒤, 검토 중인 배치 경로에서 학습 데이터를 생성하는 데 활용할 수 있다.

모델 단계에서는 최신·인기 기사와 기사 유사도 기반 추천을 비교 기준으로 두고 NRMS를 검토할 수 있다. 이력이 없는 방문자에게는 기본 추천을 제공하고, 이력이 짧은 방문자와 충분한 방문자를 나눠 평가하는 방식이 적절하다. 필요한 데이터 규모나 성능은 아직 측정하지 않았다.

추천 API 단계에서는 POPROX의 입력·출력 분리와 모델 관리 절차를 참고할 수 있다. CHAMELEON은 세션 추천 방식의 참고 자료로 두고, 오래된 실행 환경을 그대로 채택할지는 별도 검토한다.

## 확인 범위와 남은 검토

- 저장소 README, NRMS 노트북, EB-NeRD 행동 전처리 코드, MIND 공식 설명을 확인했다. 전체 코드 감사와 서비스 실행 검증은 수행하지 않았다.
- 확인한 자료 중 우리 수집 API → Cloud Storage → BigQuery 경로 전체와 동일한 구현은 찾지 못했다. 해당 경로는 우리 설계안으로 남아 있다.
- 코드 재사용 전에 해당 파일의 라이선스와 의존성 호환성을 확인해야 한다. 코드 라이선스와 기사·데이터셋 이용 조건은 별개다. MIND 공식 사이트는 연구 목적 이용 조건을 안내한다.
- 사용자 식별 방식, 실제 화면 노출 판정, 이벤트 재전송과 중복 제거, 클릭 관찰 기간은 우리 서비스에 맞게 정해야 한다.
- 이 문서는 기술 검토 자료다. 공개 프로젝트의 성능 수치를 우리 프로젝트의 성능으로 인용하지 않는다.
