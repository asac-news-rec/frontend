# 프론트엔드 보안 가이드

> Last Updated: 2026-11-03

## 방문자와 이벤트

- 비로그인 방문자 쿠키는 식별 표식이며, 서버 SQLite에는 해시와 독자 ID가 저장됩니다. 원본 토큰이나 쿠키 값을 로그·테스트 출력·PR에 남기지 않습니다.
- 독자 식별자와 행동 이벤트는 필요한 목적과 보존 범위를 명시합니다. 실제 데이터와 가상 테스트 데이터를 분리합니다.
- 화면에 기사·독자 데이터를 넣을 때 안전한 DOM 출력 방식을 사용합니다. 외부 HTML을 신뢰하지 않습니다.
- 이벤트 전송은 계약의 필드, 시각, 단위, 중복 처리 규칙을 확인하고 개인정보가 불필요하게 담기지 않도록 합니다.

## 로컬 데이터와 시크릿

- `.env`, `data/`, `*.sqlite*`, API 키, 인증 토큰, 개인 식별 정보를 커밋하지 않습니다.
- Docker `visitor-data` 볼륨은 재기동 뒤에도 남습니다. 삭제 명령은 명시적 요청이 있을 때만 사용합니다.
- 예시 설정을 공유할 때는 비밀값을 비운 파일만 사용합니다. 커밋 전 상태와 diff를 확인합니다.

## GitHub Actions와 네트워크

- workflow `permissions`는 필요한 최소 권한만 부여합니다. PR 제목·본문처럼 외부 입력을 shell 명령에 직접 삽입하지 않습니다.
- 시크릿은 workflow 파일에 하드코딩하지 않습니다. Claude 자동 리뷰 workflow와 그 시크릿은 아직 설치하지 않았습니다.
- 공개 포트, Origin 허용 범위, 쿠키 속성, CORS 또는 외부 API 접속을 바꾸는 PR은 노출 범위와 검증 결과를 적습니다.
- 보안 관련 변경은 실제 요청과 응답, 인증 실패, 재시작 뒤 데이터 유지 여부를 검증합니다.
